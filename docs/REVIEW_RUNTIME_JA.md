# 区間確認と長尺検証

1. 同じComfyUIワークフローでStudioを開き、右側の「候補」から区間確認を開始します。モデル・シード・素材・プロンプト・出力設定を最初の実行で記録します。
2. プレビューで現在候補を確認します。つなぎ表示は採用済み区間の末尾最大2秒と現在候補の先頭最大3秒です。やり直しは候補区間だけに適用します。
3. 採用後、次の区間を生成します。続きから作業する場合は通常どおりComfyUIでワークフローを保存し、同じワークフローのStudioを開きます。
4. 最終候補を採用して書き出します。Long videoは区間単位で書き出し、元音声を配置済みの場合はその音声を使います。

最終区間が採用済みで、後段のSave Videoだけ失敗した場合は、保存先を直して **保存をやり直す** を選びます。対応する保存データと同じ生成条件を使う場合、0.13.7の公開版から更新しても再生成せず保存を再試行できます。区間の生成・プレビュー作成・内部の書き出しが途中で止まった場合は **処理を再開** を使います。

生成中間データは `<ComfyUI output>/h3_continuum_ez/runs/<run>` に保存します。プレビューの再作成と書き出しの再開では保存済みデータを使います。確認途中で入力やファイルが変わった場合は前の設定に戻すか、新しい確認を開始してください。

### 「つなぎを見る」の境界診断

右側の「候補」で **つなぎを見る** を押すか、タイムラインの境界 **⋈** を押すと、保存済みプレビューの診断結果が「候補」欄に表示されます。採用後やワークフローを開き直した後も、同じ区間を確認できます。診断時に生成キューは使いません。

通常版Continuum v3.10.4の判定を、境界直前の最大8フレームと直後の最大6フレームに適用します。表示時刻はタイムライン上の位置です。平均輝度の差は黒から白までを100%とした値で、フレーム間の変化量は周辺フレームに対する倍率です。「急な変化は検出されませんでした」は、この短い窓で明滅や動きの段差などが検出されなかったという意味です。長時間の色の変化や人物の同一性は判定の対象外です。

## P4 長尺の比較

タイムラインは生成済みの画像をフィルムストリップで表示し、未生成時は設定された画像を表示します。画像のクリックは選択・移動だけで、自動再生しません。区間境界の「⋈」から「つなぎを見る」を開けます。採用済みのつなぎも同じ確認Runから参照できます。まだプレビューがない境界は、その時刻へ移動して未生成であることを表示します。候補の確認・やり直し・採用・再開・最終書き出しは右側の「候補」にまとめています。

既存の一括生成と区間確認を、同じモデル配線・シード・素材で比較します。6区間以上を使い、継続と場面転換、音声のあるケースを確認します。`manifest.json` から採用区間のフレーム境界を読み取れます。

```powershell
python tools/review_video_qa.py before.mp4 after.mp4 --manifest manifest.json
python tools/review_video_qa.py sample.mp4 --join 192 379 --cut 566
```

比較結果には境界前後の明るさ、フレーム間の変化量、細部の強さ、境界時刻の音声の変化量が出ます。場面転換は `cut` として表示します。数値の差がある箇所では元の映像を再生し、意図した照明やカメラの動きと、意図しない停止、人物・背景の変化を確認します。

ローカル検証はCPUの代替サンプラー、実ComfyUI CoreのCPU出力経路、隔離ブラウザーで行います。実GPUの画質と実機の消費メモリーはユーザー側の生成結果を取得してから判定します。
