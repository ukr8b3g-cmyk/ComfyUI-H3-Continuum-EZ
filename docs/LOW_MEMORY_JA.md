# EZの省メモリー出力

Continuum 3.10.2のDisk-backedバッファ・容量確認・Windowsの寿命管理・一時ストレージ管理を再利用します。途中再開、Run/Take、Decode Cache、Second Passは追加していません。

## Studioからの書き出し

新規Timelineでは「動画保存」が既定です。音声付きMP4をComfyUIの `output/h3_continuum_ez` に保存し、Studioで再生できます。Engineのvideo端子からも完成動画を利用できます。

ページを再読み込みしてStudioを開くと、ComfyUIの実行履歴から同じワークフロー・Timelineの前回の動画を探します。タイムラインの設定が生成時と同じなら、再生位置がタイムラインと連動します。編集後は「前回の動画」から個別に再生できます。自動復元には、実行履歴と保存済みMP4の両方が必要です。

「動画＋画像」は、動画に加えて画像処理用のフレームデータを出力します。連番画像ファイルを保存する設定ではありません。既存の画像処理経路がある場合は必要な出力を自動で選ぶため、配線を外したり、つなぎ替えたりする必要はありません。画像データが必要な場合は全フレームのバッチも作成するため、動画だけの出力よりRAMを使います。

「動画保存」は内部でLong video方式を使い、画像データが不要な場合は全尺の画像バッチを作らず、区間ごとに生成・デコード・保存します。画像データも必要なワークフローでは、自動的に画像を含む方式を使います。「自動」はワークフローの出力設定を使用します。

「自動分割」は指定した「分割間隔（秒）」を目安に、ショットを継続区間へ分けます。初期値7.5秒、設定範囲2〜15秒です。15秒のショットも2区間に分かれます。入力値7.5はそのまま保存し、実際の区間時間をフレーム単位へ調整します。オフでは各ショット15秒以下が必要です。全体のフレーム数を先に確定し、内部の丸めを累積しません。

短い区間ほど一度に扱う領域は小さくなりますが、モデルとVAEの切替回数が増えます。まず既定の7.5秒から、環境に合わせて調整してください。設定はTimelineに保存され、動画だけの場合にも、画像を含む場合にも適用されます。

原音もPCMをディスク上に順次組み立て、音声VAEのガイドは一区間＋継続context分だけエンコードします。入力画像は当該区間で必要なものだけを、出力サイズに縮小してからfloat化します。長い音声をブラウザーへ追加する際は、音声要素のメタデータで長さを取得します。120秒超は全長の波形画像作成を省き、ブラウザーに全長AudioBufferを作りません。

区間ごとにMODELとVAEの切替が発生し得るため、速度改善を保証しません。

## 一時ストレージ

Studioの「一時ストレージ」、またはComfyUI設定の `H3ContinuumEZ → Storage` から開きます。

- 空欄：ComfyUIのtemp内にあるEZ専用領域。
- 保存先指定：サーバー側の絶対パス。通常Continuumと混ざらないよう、指定先の下に `h3-continuum-ez` 専用フォルダーを設けます。
- 検証：書き込み・メモリマップと空き容量を確認。
- 保存：以降の処理へ適用。既存の一時ファイルを移動しません。
- 使用量：現在／以前の保存先、使用中／削除可能／判定不能、空き容量を表示。
- 未使用ファイル削除：実行中・待機中のQueueが空のときだけ可能。Tensorの参照が残るファイル、判定不能なファイルは保護します。

通常Continuumの設定、Run、Take、完成動画は変更しません。MP4の保存先はComfyUIのoutputで、一時保存先の設定では移動しません。

途中再生用の低解像度MP4はComfyUIのtemp内の専用領域です。使用量は一時ストレージ画面に別表示します。使用中の実行は保護し、未使用になって24時間を超えたもの・容量目安2 GiBを超えた古いものを、次回保存／清掃時に回収します。1回512 MiBを目安に追加プレビューを止め、最終出力は継続します。「未使用の一時ファイルを削除」でも消せます。画像・動画の最終出力は削除対象に含めません。

## 解像度

Studioの「出力サイズ」で設定元を「Studioで設定」にし、アスペクト比を8種類から選択、メガピクセルを数値入力します。新規Timelineの初期値は16:9・0.3 MP（736×416）、0.6 MPなら1024×576です。幅×高さを即時表示します。H3用に両辺を32の倍数へ自動調整するため、multipleの操作は不要です。全ショット共通で、Studio設定時はEngineのwidth/height（外部接続を含む）より優先します。

外部Resolution Selectorを使う場合は設定元を「Engine」に切り替え、Selectorのmultipleを32にしてください。既存Workflowにサイズ設定がない場合も、Studioから反映・実行すると既定の16:9・0.3 MPを保存します。設定元にEngineを指定した場合は外部サイズを使い、「Studio換算」の表示はStudioに切り替えたときの目安です。Studioを開かず既存Workflowを実行する場合は従来のEngineサイズを使用します。MP入力範囲0.01〜16は入力検査の範囲で、モデル・GPUで生成可能なサイズを保証するものではありません。

通常Continuumの `Native 768` は短辺768ピクセルで、0.768 MPではありません。16:9に近い手動サイズなら1376×768など、両辺を32の倍数にします。

## 制約と確認範囲

一度に処理する1内部区間分、MODEL/VAE、条件付けにはRAM/VRAMが必要です。ディスクバッファにはOSのページキャッシュも使われるため、RAM使用量ゼロや一定量を保証しません。上限は1ショット2〜600秒、最大16ショット、合計実尺60分です。15秒以下の既存ショットは従来の生成尺を維持します。

CPU模擬Sampler/VAEで通常出力とディスク出力の一致、複数ショットのMP4フレーム数と音声、中断時の一時ファイル処理、参照中のファイル保護を確認。v0.13.0では832×480・379フレームのFastH3 2区間を普段のComfyUIで実GPU生成し、Long videoで全尺RGB1.69GiBを未確保、音声内容と時刻の保持を確認。境界補正は末尾2＋先頭5フレームだけで評価します。観測プロセスRSS最大24.09GiBはモデルを含み、他の尺・モデルでのRAM量や時間単位の長尺を保証しません。詳細は[検証記録](RELEASE_v0.13.0_VALIDATION_JA.md)を参照してください。

導入後はComfyUI再起動とブラウザーの強制再読み込みが必要です。
