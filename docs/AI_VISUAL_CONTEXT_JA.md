# AI文章への画像・時間・サイズ入力

2026-11-07、v0.10.1を基準に実装・検証した変更です。v0.11.0に収録。以下の各節は検証時点の記録です。

- モデルと原文／AI文／AI生成の操作は維持。画像選択ドロップダウンを自動参照の枚数表示へ変更。
- ショットAIは、実際の個別参照または継承する共通参照、開始・最終画像を重複除去して入力。画像順と役割を文章入力に対応付ける。
- 目標秒数、24fpsで整列した生成時間、出力アスペクト比と幅・高さを入力。
- Studioのサイズを優先。Engine指定は実配線から幅・高さを取得し、標準Resolution Selectorと整数定数にも対応。未確定の動的サイズを推測せず、AI操作時にエラーを表示する。
- ショットAIへ共通文を送らない。共通AIへ個別ショットの本文・演出・時間・専用画像を送らない。共通参照と共通文だけを対象とする（出力サイズは全体共通）。
- 最大11画像、1画像50万画素、1リクエスト合計200万画素以内。縦横比を保った解析用コピーを使い、元画像を変更しない。
- 新しい依存条件契約は `h3ez-assist-visual-v3`。旧AI文は旧契約の条件で保持。新AI文は秒数・サイズ・参照変更でも無効化し、元文章と保存AI文を失わない。画像バイト列は採用時と動画生成時に再確認。
- EngineサイズがAI生成時から変わった場合、動画生成時にも確認し、原文へ戻す。通常のH3 Sampling、Continuum vendor、モデル選択、ワークフロー配線は変更しない。

入力確認ボタンは、その後のユーザー指示により撤去しました。以下にある入力確認のダイアログは検証途中の仕様です。現在は生成前に自動で検証します。

## 確認

- Python 277件、JavaScript 82件成功。複数画像の順番、継承／個別、最大11枚の画素上限、時間・サイズ、共通文との分離、古い結果の拒否、Python/JSの契約一致、既存生成経路を確認。
- 独立Chromium画面で2画像の自動入力、原文／AI文切替、共通文保持、生成プロンプトの合成、秒数変更後の無効化を確認。文章推論は代替応答であり、実モデル検証ではない。
- 普段のComfyUI_Wへ反映済み。当初の正本と導入先141ファイルのSHA-256一致を確認。公開・コミットは未実施。
- ユーザーによる再起動後、実サーバーの `max_ai_images: 11` と必要ノードの存在を確認。
- 実ComfyUI ClassicのStudioでAI生成。ジョブ `e262be49-80ba-4268-9d50-dfe0d336a3ac` が18.169秒で成功。P-H3 upsampler、LoadImage 2ノードと `images.image1`／`images.image2` を使った非キャッシュの実推論。
- 実際の文章入力に、2つの画像IDとの対応、目標5秒・生成5.1667秒、2:3・576×864が含まれることを履歴で確認。共通文は空のcontextとして除外。
- 実画面で原文→AI文→原文の切替、共通文の保持、5秒→8秒の変更によるAI文の無効化、5秒へ戻した後の再選択を確認。別名保存したWorkflowでも元の本文・共通文と2画像の受領記録を保持。
- **モデル出力の制約：** この試行では2人を描写できた一方、「single frame」「speech bubble」「nothing moves」など、動画の動作指定と合わない文章も出た。画像・時間・サイズの連携成功と、文章内容の適切さは別に判断する。モデルは指定どおり変更していない。

## 動画の速度比較（実GPU確認済み）

## 追加のUI・分割修正（反映・実GPU確認済み）

- タイムラインの動画サムネイルをショット全体の背景に重ね、名前・時間・生成状態を前面に表示。上下の分割を廃止。
- 入力確認に右上の閉じるボタンとEscape操作を追加。出力設定も閉じるボタン・外側クリック・Escapeで閉じる。
- 出力名を「自動」「動画保存」「動画＋画像」に整理。画像はIMAGEデータであり、連番画像の保存ではない。
- 有効なIMAGE出力先がある場合は、自動的に画像も返す経路へ切り替える。手動の配線変更は要求しない。未使用枝は引き続き動画の直接保存を妨げない。
- 自動分割の初期値は7.5秒。15秒以下にも指定間隔を適用する不具合を修正。入力値7.5は保持し、生成時間はH3のフレームグリッドに合わせる。目標15秒は2区間、合計362フレーム（約15.083秒）、区間は8秒＋約7.083秒となる。
- ユーザーによる再起動後、実サーバーの入力確認で15秒・2区間・362フレームを確認。Studioの「反映・キュー追加」からFastH3を実行し、109.234秒で成功。追加LoRAなし、モデル・サンプラー・注意機構の配線を維持。
- 15秒の検証動画は256×384（0.1 MP）・24fps・362フレーム・AAC音声。全フレーム・音声を最後までデコードし、非ゼロの音量を確認。2区間の実Samplingと39フレームの継続Contextをログで確認。
- カメラ追従を両区間、継続動作を後続へ、一度の動作と2行のセリフを該当区間だけへ送る文章変換を、実際に実行したplanで検査。文章が接続されていることと、モデルが厳密にその演出・発話時刻へ従うことは別。画質・発話の厳密な再現性は定量評価していない。

- 入力確認の右上×・Escape、出力設定の×・Escape・外側クリックを実画面で確認。入力値7.5の保存も、実行履歴と完成MP4のWorkflowで一致。
