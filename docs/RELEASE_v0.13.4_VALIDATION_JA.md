# v0.13.4 ボタン反応・キュー状態表示の検証

2026-11-10。v0.13.3からのUI/状態追跡の限定修正です。

## 原因と変更

実画面のボタン中心で、他要素の重なりなし、disabled=false、pointer-events=autoを確認しました。現在の入力では映像10.125秒に配置音声60.002秒が残り、49.877秒の不足で送信前検査に止まっていました。直前の60.417秒の状態は実際に受付され、後に中断されていました。入力警告がキュー終了状態を上書きし、短い入力エラーではボタンも元の見た目へ戻るため、操作結果が分かりづらい状態でした。

- 確認中/送信中はボタンの文言と色を変更。拒否時は赤色の未送信、受付後は緑色と✓を表示します。
- 具体的な入力エラーをヘッダーの独立した警告欄へ表示。既存の映像尺合わせも警告のそばから実行できます。
- 実行/完了/失敗/中断の状態を入力警告で隠さず保持します。短時間終了やイベント取りこぼしは、一致する履歴から復元します。
- 履歴はWorkflow、出力に接続されたTimeline、既知のジョブIDや投入時刻で照合し、他Workflowや未使用経路を混同しません。

## 実ComfyUI・実マウス確認

ユーザーの選択に従い、配置クリップだけを開始0/長さ10.121秒へトリム。映像は10.125秒、元の音声素材60秒とSource INは保持。プロジェクトは変更前に保護し、ノード反映とブラウザー更新後の保持を確認しました。

実ComfyUIで履歴からRender stoppedの復元を確認。プレビューをミュートにし、ネイティブのマウス座標クリックからキュー追加。✓ Apply and Queue、緑色、Studio内Runningを同時に観測しました。サーバー履歴でもexecution_startを確認しています。

その後のexecution_interruptedについて、ユーザーが自身で停止・キャンセルしたと明示しました。キュー受付・実行開始を確認した結果であり、GPU生成完了・完成動画・画質の成功とは扱いません。公開時は追加の実画面確認・再起動・GPU生成を行っていません。

モデル配線は実行履歴でも変更前と一致。シードの手動編集や生成後制御の設定変更は行わず、既存randomizeによる通常の値更新は維持しました。同じ固定seedでの映像比較を実施したという意味ではありません。配布の両テンプレート、生成Python、通常Continuum由来22モジュールも保持しています。
