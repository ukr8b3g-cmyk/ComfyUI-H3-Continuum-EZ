# v0.13.2 境界補正と実GPU検証

2026-11-08。v0.13.1を基準に、既存の露出・色補正後に残る動きの段差を限定補正。通常Continuumのブレンド・Auto安全判定を変更せず再利用し、固定窓（前2枚/次5枚）と先頭最大2枚だけの補正で、全尺RGB確保を追加しません。Scene Cut・速い動き・局所フラッシュは保護します。

## 原因と比較条件

トリム前のVAE復元映像に露出パルスがあり、既存露出補正後にも通常Continuum V3の解析でmotion_hitchが残りました。Context39fとモデル到達は正常。1〜3枚の接合位置変更では改善不足だったため採用せず、境界での空間/動きの再現差を補正しました。モデルとVAE内部の寄与を完全分離したとの結論ではありません。

普段のWindows ComfyUIでユーザー再起動後に修正後を新規実GPU生成し、直前の同条件report実GPU出力と比較。FastH3 OmniRef8step INT8、基準seed38527745983564、派生seed520966230086438534/303231056385338123。モデル配線、Sampler/VAE/Contextと両テンプレートを維持。832×480/24fps、2チャンク192+187=379フレーム（15.791667秒）。修正後約359.62秒。前後ともContext39f、実wrapper検証8回・失敗0。

- 完成MP4の境界5フレーム窓の最大変化：0.032628→0.023230（約28.8%低減）。
- 境界frame192の推定移動量中央値：2.054→0.498px。境界5フレーム内の最大中央値：2.054→1.506px。
- 379フレームと表示時刻を保持。入力音声AAC682パケットの内容・PTS/DTS・長さが完全一致。
- 人物、服装、座席/窓の配置を保持し、急な境界移動を緩和。ただし補正2枚の局所的な柔らかさが残ります。
- 全尺RGB1.69GiBは未確保。判定・候補保持は尺に比例しない固定枚数。RSSサンプル最大24.52GiB、起動以来のpeak working set26.28GiBはモデル/VAE等込みの値で、補正単体や修正前後のRAM比較ではありません。

Python346・JavaScript99件成功、失敗/スキップ0。通常Continuum由来22モジュール、公開2ノード、モデル配線、シード、既存の開始/終了画像・音声経路を維持。Images/実PyAV Long videoのCPU統合試験も実施。版番号・文書更新後のGPU再生成は行っていません。
